# 学習計画: DB設計/データエンジニアリング

対象テーマ: 2026年 第1弾「データ基盤構築」(SQL × データパイプライン構築 × DB設計)
現在レベル: 0 → 目標レベル: 2(このミニ課題での到達ライン)
状態: 未着手

## 学習内容

- 正規化(第1〜第3正規形)の考え方
- ER図の書き方(エンティティ・リレーション・カーディナリティ)
- 主キー/外部キー制約、一意制約、NOT NULL制約の設計
- DDL(CREATE TABLE文)の記述

## 題材データ

業務に近いダミーデータとして「小売店の受注管理」を想定する。最低限、以下のエンティティを含む正規化されたスキーマを設計する。

- 顧客(customers)
- 商品(products)
- カテゴリ(categories) — productsから分離して正規化の理由を示す
- 注文(orders)
- 注文明細(order_items) — ordersとproductsの多対多を解消するブリッジテーブル

## 環境

Docker上のPostgreSQLを使用する(`docker run` または `docker-compose.yml` でローカルに構築)。

## ミニ成果物の仕様

1. ER図(手書き・ツール問わず、画像またはMermaid記法で可)
2. 正規化されたテーブル定義一式のDDL(CREATE TABLE文。主キー・外部キー・NOT NULL等の制約を含む)
3. サンプルデータ投入用のSQL/スクリプト(customers/products/categories/orders/order_itemsそれぞれ最低10件程度)
4. README: なぜこの正規化・テーブル分割にしたかの設計判断の説明(例: なぜcategoriesを分離したか、なぜorder_itemsが必要か)

## 合格基準(事前定義・着手後の変更禁止)

1. ER図が提出されている
2. 第3正規形相当まで正規化されており、設計判断の理由がREADMEで説明されている
3. 実行可能なDDL(主キー・外部キー制約を含む)が提出されており、Docker上のPostgreSQLで実際にCREATE TABLEが通る
4. サンプルデータ投入スクリプトが提出されており、実行後に各テーブルにデータが入っている
