### 2. JOIN・集約クエリ

顧客ごとの累計購入額ランキング。

```sql
SELECT
    c.customer_id,
    c.customer_name,
    SUM(oi.quantity * oi.unit_price) AS total_amount
FROM customers c
JOIN orders o       ON o.customer_id = c.customer_id
JOIN order_items oi ON oi.order_id = o.order_id
GROUP BY c.customer_id, c.customer_name
ORDER BY total_amount DESC;
```

カテゴリ別売上集計(3テーブル以上のJOIN例)。

```sql
SELECT
    cat.category_name,
    SUM(oi.quantity * oi.unit_price) AS category_sales
FROM categories cat
JOIN products p      ON p.category_id = cat.category_id
JOIN order_items oi  ON oi.product_id = p.product_id
GROUP BY cat.category_name
ORDER BY category_sales DESC;
```

### 3. ウィンドウ関数

顧客ごとの注文金額ランキング(`RANK()`)。

```sql
SELECT
    c.customer_name,
    o.order_id,
    SUM(oi.quantity * oi.unit_price) AS order_amount,
    RANK() OVER (
        PARTITION BY c.customer_id
        ORDER BY SUM(oi.quantity * oi.unit_price) DESC
    ) AS amount_rank
FROM customers c
JOIN orders o ON o.customer_id = c.customer_id
JOIN order_items oi ON oi.order_id = o.order_id
GROUP BY c.customer_id, c.customer_name, o.order_id;
```

前回注文からの経過日数(`LAG()`)。

```sql
SELECT
    customer_id,
    order_id,
    order_date,
    order_date - LAG(order_date) OVER (
        PARTITION BY customer_id ORDER BY order_date
    ) AS days_since_last_order
FROM orders;
```

`RANK()`は「同点なら同順位、次の順位を飛ばす」、`LAG()`は「1つ前の行の値を取得する」関数です。`PARTITION BY`は「顧客ごとに」集計をリセットする役割を持ちます。

### 4. 実行計画とインデックス

まず現状の実行計画を見ます。

```sql
EXPLAIN ANALYZE
SELECT * FROM order_items WHERE order_id = 123;
```

出力に `Seq Scan on order_items` と表示された場合、テーブル全件を舐めて探しています(全表スキャン)。`Execution Time` の値をメモしておきます。

データ量が少ないとPostgreSQLが自動的にインデックスを使わない(全表スキャンの方が速いと判断する)ことがあります。差を体感するために、まず件数を増やします。

```sql
INSERT INTO order_items (order_id, product_id, quantity, unit_price)
SELECT
    (random() * 1 + 1)::int,
    (random() * 3 + 1)::int,
    (random() * 5 + 1)::int,
    100.00
FROM generate_series(1, 5000);
```

(order_id/product_idの範囲は自分が投入した件数に合わせて調整してください。外部キー制約があるので、存在するIDの範囲内で生成する必要があります)

次にインデックスを追加します。

```sql
CREATE INDEX idx_order_items_order_id ON order_items(order_id);
```

再度同じクエリのEXPLAIN ANALYZEを実行します。

```sql
EXPLAIN ANALYZE
SELECT * FROM order_items WHERE order_id = 123;
```

`Index Scan using idx_order_items_order_id` に変わり、`Execution Time` が短くなっていれば成功です。この Before/After(実行計画の種類・実行時間)をそのままREADMEに貼り付けてください。
