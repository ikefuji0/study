# 学習計画: SQL

対象テーマ: 2026年 第1弾「データ基盤構築」(SQL × データパイプライン構築 × DB設計)
現在レベル: 1 → 目標レベル: 2(このミニ課題での到達ライン。将来的にはテーマ全体を通じて3を目指す)
状態: 未着手(DB設計のミニ課題合格後に着手)

## 前提

`skills/DB設計/` で構築したスキーマ(customers/products/categories/orders/order_items)に対してクエリを書く。DB設計のミニ課題合格後に着手する。

## 学習内容

- 複数テーブルのJOIN(INNER/LEFT)、GROUP BYと集約関数
- ウィンドウ関数(RANK, ROW_NUMBER, LAGなど)
- 実行計画の確認(EXPLAIN ANALYZE)とインデックス設計
- 既存業務(Oracleへの参照クエリのみ)からの脱却として、パフォーマンスを意識したクエリ設計

## ミニ成果物の仕様

1. 3テーブル以上をJOINした集計クエリ(例: 顧客ごとの累計購入額ランキング、カテゴリ別売上集計)
2. ウィンドウ関数を使った分析クエリ(例: 顧客ごとの購入順位、前回注文からの日数)
3. パフォーマンス改善の実演: 対象クエリに対しEXPLAIN ANALYZEで実行計画を確認 → インデックスを追加 → 再度EXPLAIN ANALYZEで比較し、Before/Afterの実行時間・実行計画の変化を示す
4. README: 各クエリの目的と結果、パフォーマンス改善のBefore/After

## 合格基準(事前定義・着手後の変更禁止)

1. 3テーブル以上のJOINを含む集計クエリが動作する
2. ウィンドウ関数(RANK/LAG等)を使ったクエリが最低1つ含まれる
3. EXPLAIN ANALYZEでの実行計画確認と、インデックス追加前後の実行時間比較(Before/After)が示されている
4. クエリと説明がREADMEにまとまっている
